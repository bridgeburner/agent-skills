# Prose guidance

## Purpose and cadence

Open with what the document is about, who needs it, and what decision or action
it supports. Vary sentence and paragraph shape when the writing has settled into
a repeated rhythm. A short sentence can land a point after a longer explanation;
some ideas need a table or one line.

Read three adjacent sentences aloud when the prose feels generated. Change the
shape of one only if the repetition distracts from the idea.

## Headings and structure

A heading is an address label. Name the subject rather than selling it. Avoid
using a title and a subtitle to say the same thing; keep a subtitle when it adds
a concrete fact.

Use a real list for parallel items and a numbered sequence when order matters or
readers will cite the steps. Do not turn enumeration into a slogan. Tables are
usually clearer than prose for several parallel dimensions. Keep one main idea
per paragraph and put the decision or result near the top.

## Language

Prefer concrete, active sentences with a real subject and a checkable claim:

| Avoid | Prefer |
| --- | --- |
| Postgres owns the run | The run row holds the delivery state |
| The clock asks for capacity | Cloud Scheduler calls the tick |
| We surface visibility into failures | The page shows failures |
| This unlocks the ability to retry | This lets the worker retry |

Remove stock filler, slogans, marketing verbs, and self-answered rhetorical
questions. Phrases such as “here's the thing,” “best-in-class,” or “at the end
of the day” usually delay the sentence's subject. State the claim directly
instead of using “it's not X, it's Y” constructions.

Use punctuation for meaning. An em dash, arrow, or middot is fine when it marks
a real relationship, diagram, or metadata field; repeated decorative marks make
the rhythm and hierarchy harder to read. Avoid turning every list item into a
bold label followed by a colon.

Name uncertainty where it exists. “Not observed in dev” and “documented” do not
mean “never happens” or “verified.”

## Rewriting

De-slopping an existing document changes presentation, not substance. Preserve
facts, caveats, requirements, and links. If the document is consequential,
extract a quick fact list before rewriting and compare it with the result.
